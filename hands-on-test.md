# Hands-On Skills Demonstration: Current Events Mini-Site

**Format:** Individual, hands-on class assessment  
**Suggested time:** 50–60 minutes  
**Goal:** Demonstrate that you can organize a project, research and cite a story, write Markdown, create a simple web page, use Git, and explain your process.

## Scenario

You are creating a small “Current Events Mini-Site” for classmates. Your site should help a reader understand one global story and one AI story. The focus is not on making the most complicated website; it is on showing that you understand every part you create.

## Required Deliverables

Create a new repository with this minimum structure:

```text
current-events-mini-site/
├── README.md
├── index.html
├── styles.css
├── global-event.md
├── ai-event.md
├── images/
└── notes/process.md
```

You may add files and folders if they make the project clearer.

## Tasks

### 1. Organize the Project — 15 points

- Create the required files and `images/` folder.
- Use descriptive, lowercase, hyphenated filenames.
- Keep article writing, visual assets, and process notes separate.
- In `notes/process.md`, explain why you chose your structure in 2–4 sentences.

### 2. Research and Write Two Briefs — 25 points

- Write one original **Global Events** summary and one original **AI Events** summary.
- Each summary should be 150–250 words.
- Use at least one credible, direct source for each story.
- Include a clickable source link and attribute facts in the summary.
- Do not copy whole sentences from the source.

### 3. Use Markdown Well — 15 points

Each article must include:

- A title and date
- At least two headings
- Paragraphs with readable spacing
- One useful external source link
- One image with meaningful alt text **or** a clearly labeled placeholder explaining the image you would use
- One small Mermaid diagram that explains a relationship in the story

### 4. Build a Homepage — 15 points

Your `index.html` must include:

- A site title and one-sentence purpose
- Links to both article files
- A simple two-section layout or two article cards
- At least one image, color choice, or typography choice that supports the topic
- A `styles.css` file linked from the page

### 5. Document Your Prompting and Decisions — 10 points

In `notes/process.md`, include:

- One research prompt you used or would use
- One design or image prompt you used or would use
- One revision you made after checking the result
- A sentence explaining how you checked facts and sources

Using AI is allowed only if your instructor allows it. If you use it, document what it helped with and verify the final information yourself.

### 6. Use Git and Publish — 20 points

- Run `git status` before your first commit.
- Make at least **two meaningful commits**. Example: one for project structure, one for content and styling.
- Use clear commit messages.
- Push the repository to GitHub.
- If time and class setup allow, publish with GitHub Pages and include the live URL in the README.

## Evidence to Submit

Submit:

1. The GitHub repository URL
2. The GitHub Pages URL, if publishing is part of the class session
3. A short screen recording or live demonstration (2–3 minutes) in which you:
   - Show the project folders
   - Open both articles
   - Point out a source link and Mermaid diagram
   - Show `git log --oneline`
   - Explain one choice you made about organization, research, or design

## Grading Rubric

| Skill | Excellent | Meets expectations | Needs work |
| --- | --- | --- | --- |
| Organization (15) | Clear structure, names, and explanation | Required files are organized | Files are confusing or missing |
| Research & writing (25) | Accurate, focused, original, well-sourced | Two complete summaries with sources | Missing, vague, copied, or unsourced content |
| Markdown (15) | Clean hierarchy, useful image/placeholder, effective diagram | Required Markdown elements work | Broken links, missing sections, or unreadable formatting |
| Homepage (15) | Clear, styled, and easy to navigate | Required links and styling present | Page does not clearly connect to content |
| Process notes (10) | Specific prompts, revision, and fact-checking explanation | Required decisions documented | Minimal or missing process evidence |
| Git & publishing (20) | Two meaningful commits and a live, working site | Two commits and repository pushed | Missing commit evidence or repository not pushed |

## Instructor Observation Checklist

- [ ] Student can explain where each file belongs.
- [ ] Student can describe the difference between Markdown content and HTML/CSS presentation.
- [ ] Student can open a source link and explain why it is credible.
- [ ] Student can explain one Git command they used.
- [ ] Student can explain one prompt, revision, or design decision in their own words.

## Final Self-Check

- [ ] My links work.
- [ ] My image paths work, or my placeholder is clear.
- [ ] My articles use my own writing and link their sources.
- [ ] My Mermaid diagram explains something meaningful.
- [ ] I can explain every file and command I used.
- [ ] My repository is ready to share.
